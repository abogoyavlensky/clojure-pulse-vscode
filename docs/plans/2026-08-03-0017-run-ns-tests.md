# Run Tests in Namespace Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Run Tests in Namespace" command that loads the current buffer, runs every top-level `deftest` sequentially in the active REPL, paints a gutter mark per test as each finishes, and shows the namespace's aggregate verdict in the status bar.

**Tech Stack:** TypeScript VS Code extension, nREPL over bencode, mocha (tdd ui) via `@vscode/test-cli`.

---

## Design

Settled with the user; generalizes the single-test machinery from
`docs/plans/2026-08-02-1625-run-test-at-cursor.md` (runner expression, cross-runtime
namespace handling), `…-2250-test-status-gutter-marks.md` (last-command gutter
report), and `…-2338-test-status-bar-and-polish.md` (status bar).

### Semantics

- **Per-var sequential runs.** Each enumerated test runs with the *existing*
  single-var runner expression, in buffer order, one eval per test. This keeps
  behavior identical on JVM and let-go (whose report output has no test names,
  so aggregate-run parsing could never mark per test), reuses the proven
  snippet, and updates the gutter progressively. Accepted caveat, documented:
  `:once` fixtures run once **per test** (inherent to `run-test-var`/`test-vars`
  called per var), not once per namespace as `run-tests` would.
- **Always load the buffer first.** "Run all tests" means "test this buffer":
  one `session.loadFile` of the document (same on-disk `filePath`/`fileName`
  handling as `evalFile`) refreshes helpers and every deftest, and guarantees
  the enumerated vars exist. No find-ns probe here — the single-test command
  keeps its probe-and-define flow untouched.
- **Discarded deftests are excluded from bulk runs.** `#_(deftest …)` (and
  quoted/syntax-quoted forms) are not defined by the load, so running them
  would fail on an unresolved var — and discarding is disabling. Deliberate
  difference from `testAtCursor`, where explicit cursor intent runs a
  discarded test.
- **No inline eval decorations** for the bulk run — per-test results live in
  the gutter marks and hovers; the output channel streams everything.
- **Errors:** a test whose runner eval reports `err` gets a fail mark and the
  run continues to the next test (test runners don't stop on red). A thrown
  transport error (`catch`) aborts the remainder, clears the status bar, and
  reports via `reportEvalError`. **Because bulk runs have no inline
  decoration, abort errors must be visible some other way:** a load failure
  or an in-ns failure shows `vscode.window.showErrorMessage` with the
  error's first line (the `reportEvalError` convention — a notification, no
  focus moved) and clears the status bar. Early aborts (no session, no
  deftests, load failure) never paint marks.
- **Status bar:** `running(<ns name>)` during the run; on completion,
  `finish` with the namespace name, aggregate status (fail if any test
  failed), and summed fail/error counts. With no ns form, the name falls back
  to `"tests"`. A buffer with several `ns` forms runs all its tests but is
  labeled with the first namespace's name (documented, not engineered
  around). Token-guarded staleness as today.

### Components

1. **`testsInText`** (`src/repl/forms.ts`):
   ```ts
   /** Every runnable top-level deftest, in buffer order. Discarded or
    *  quoted deftests are excluded — a load-file does not define them. */
   export function testsInText(text: string): TestAtCursor[];
   ```
   Walks top level with the existing reader (the `skipTrivia`/`readForm` loop);
   the deftest-qualification + name-extraction logic currently inline in
   `testAtCursor` (list check, `evaluableStart`, head token, `readLiveChild`
   name) is refactored into one internal helper both functions call. For
   `testsInText`, a form whose `evaluableStart` differs from its `start`
   (i.e. any `#_` marker) is excluded, in addition to quote-like prefixes.
   `testAtCursor` behavior is unchanged (existing tests pin it).

2. **`TestStatusManager` API split** (`src/repl/testStatus.ts`):
   ```ts
   beginRun(): void;                                  // wipes all marks
   track(editor: vscode.TextEditor, range: vscode.Range): string; // one pending mark
   ```
   `report`, `marks`, edit/close handling unchanged. A later `beginRun` still
   invalidates all earlier pending ids (they are simply gone from `current`).
   `runTestAtCursor` calls `beginRun()` then `track(...)`; race tests update
   mechanically.

3. **Shared run-one-var helper** (`src/extension.ts`): extract from
   `runTestAtCursor` the "run one defined test var" tail — build the runner
   expression for a name, eval with `{ ns }`, map `testStatusOf` /
   `buildStatusHover`, `testStatus.report(...)` — into a private async helper
   both commands use, returning the outcome (and counts) so callers can
   aggregate. The single-test command's probe/load/define preamble and inline
   decoration stay where they are.

4. **`runNsTests` command** (`src/extension.ts`, registered as
   `clojurePulse.runNsTests`, contributed as "Run Tests in Namespace",
   category "Clojure Pulse", no default keybinding):
   1. Guard `activeSession` + active editor (as `runTestAtCursor`).
   2. `testsInText(document text)`; empty → status-bar message
      "Clojure Pulse: no deftests in this file", nothing else.
   3. `testStatus.beginRun()`; `track` each test (keep ids in order);
      `statusBar.running(nsName ?? "tests")` where `nsName` is
      `nsBefore(text, firstTest.range.start)`.
   4. When inline results are off, `session.showOutput()` up front (the
      eval-command convention).
   5. `loadFile` the buffer; on `err` → `showErrorMessage` with the error's
      first line, `statusBar.clear`, stop (pending marks stay invisible and
      vanish on the next command).
   6. Per test, in order: compute its ns via `nsBefore(text, range.start)`.
      **When the ns is `undefined` (no ns form before the test), skip the
      in-ns eval entirely and send the runner with no `ns` param** — the
      load defined the test in the session's current namespace. Otherwise,
      when the ns differs from the previous test's (or is the first with
      one), eval `(in-ns '<ns>)` with `{ ns }` — an `err`/`namespaceNotFound`
      there shows `showErrorMessage`, clears the status bar, and aborts.
      Then the shared run-one-var helper. Accumulate summed fail/error
      counts and whether any test failed.
   7. `statusBar.finish(token, { phase: "done", name, status, fail, error })`.
   8. `catch`: `statusBar.clear(token)`, `reportEvalError`.

### Testing strategy

- Unit (`src/test/forms.test.ts`): `testsInText` — multiple deftests in order
  with correct names/ranges; non-deftest forms skipped; `#_(deftest …)` and
  `'(deftest …)` excluded; `^meta` deftest included; qualified heads included;
  unbalanced tail degrades to the tests read so far (or none) without garbage.
- Unit (`src/test/testStatus.test.ts`): update race tests to
  `beginRun()`+`track(...)`; add: two tracked marks resolve independently;
  `beginRun` wipes both.
- Integration (`src/test/replCommands.integration.test.ts`): expose
  `testStatusBar` on `ExtensionApi` so its `current()` view is assertable.
  - Two passing deftests → op order `load-file`, `eval` (in-ns), `eval`×2
    (runners, each containing its `#'name`); `marks()` has two pass entries on
    the right lines; the status bar's `current()` shows the pass view with the
    namespace name.
  - Second test fails (respond `:fail 1` + out chunk for the runner containing
    `#'second-name`) → marks pass + fail, fail hover contains the report; the
    status bar's `current()` shows the fail view with the summed counts.
  - No deftests in the buffer → no `load-file`/`eval` ops.
  - Load failure (`load-file` replies `err`) → no runner evals, no marks.
  - Existing `runTestAtCursor` tests keep passing (API split is invisible at
    the command level).
