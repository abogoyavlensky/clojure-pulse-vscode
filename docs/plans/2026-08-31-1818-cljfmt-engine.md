# cljfmt Formatting Engine Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make indent-on-Enter and Format Document produce byte-identical cljfmt output (honoring the project's `.cljfmt.edn`) via the bundled `@abogoyavlensky/cljfmt-js` library, with the existing structural rule kept as a selectable engine and as the runtime fallback.

**Tech Stack:** TypeScript (VS Code extension), `@abogoyavlensky/cljfmt-js` 0.1.0 (cljfmt 0.16.5 compiled to JS), existing scanner in `src/indent.ts`, `@vscode/test-cli` + xvfb harness.

---

## Design

### Approach

A small engine layer with two implementations behind a new setting `clojurePulse.formatting.engine` (`"cljfmt"` default, `"structural"`), governing Enter, Format Document / Format Selection, and (via the user's own `editor.formatOnSave`) format-on-save.

- The **cljfmt engine** wraps `@abogoyavlensky/cljfmt-js` — cljfmt compiled to JS, parity-tested byte-identical to the JVM CLI. Loaded at activation (not lazily — a lazy load would stall the first Enter). Synchronous, in-process, so the atomic-Enter design survives.
- The **structural engine** is today's fixed rule (`indentColumnAt` in `src/indent.ts`). It is also the cljfmt engine's runtime fallback whenever cljfmt-js throws (unbalanced mid-edit text) — the Enter path never surfaces an error.

`insertStructuralNewline` (src/extension.ts ~line 2032), the keybinding-owned Enter, the single atomic edit with folded `maintainIndent` shifts, and multi-cursor handling are preserved exactly; only the indent-column computation is swapped. `maintainIndent.ts` is engine-independent and untouched. clj-pulse (the LSP) is untouched; `indent.rs` keeps serving other editors.

### cljfmt-js API (the dependency's contract)

Installed from the release tarball URL (lockfile pins integrity):
`https://github.com/abogoyavlensky/cljfmt-js/releases/download/v0.1.0/abogoyavlensky-cljfmt-js-0.1.0.tgz`

Opaque handles — configs never cross the JS boundary as plain objects:
- `readConfig(edn: string): Config` — supports `#re`, throws on bad EDN
- `mergeConfig(base, override): Config` — override wins
- `defaultConfig: Config`
- `readNsContext(source: string): NsContext` — aliases/refers/ns-name from a file's `ns` form
- `reformatString(source, config?, nsContext?): string` — throws on unparseable source
- `cljfmtVersion: string` — `"0.16.5"`

`nsContext` exists because Enter formats a *window* (a sub-form) that lacks the `ns` form; without it, namespace-qualified indent keys in the config would not match.

### Windowed Enter (the hot path)

Reformatting the whole top-level form per keystroke is Calva's known lag (big `comment` blocks). Instead, cljfmt's rules only consult a bounded number of ancestors (`[:inner n]`, default rules max at n=2), so the probe formats a small window:

1. **Window selection.** Run the existing `Scanner` over `text[0..cursor)`. The window opener is the frame `stack[Math.max(0, stack.length - (maxInner + 1))]` — the ancestor `maxInner` levels above the form whose child the new line becomes. `maxInner` comes from config discovery (below), default 2.
2. **Balance check.** Window end = `findMatchingClose(text, opener.openOffset)`. If `null` (form never closes — mid-edit), fall back to the structural rule.
3. **Probe text.** `text[openOffset..cursor) + "\n" + PLACEHOLDER + text[afterWs..closeEnd]` where `afterWs` mirrors the command's existing skip-spaces (whitespace after the cursor is eaten), `closeEnd` = one past the matching closer, and `PLACEHOLDER` is a collision-proof symbol (e.g. `__cljp__`). The placeholder is always inserted, even before a tail — it stands for the new line's first element so `[:block n]` / `[:inner n m]` index logic sees the right shape.
4. **Probe options.** `mergeConfig(effectiveConfig, PROBE_OVERRIDES)` where `PROBE_OVERRIDES = readConfig(...)` of an EDN literal forcing every text-mutating option off so the probe only re-indents: `:remove-surrounding-whitespace? false`, `:remove-consecutive-blank-lines? false`, `:insert-missing-whitespace? false`, `:remove-trailing-whitespace? false`, `:remove-multiple-non-indenting-spaces? false`, `:split-keypairs-over-multiple-lines? false`, `:sort-ns-references? false`, `:normalize-newlines-at-file-end? false`, plus the `:align-*?` flags false. `:indentation? true` must remain. The executor verifies via the Task 4 tests that this set is sufficient (i.e. the placeholder's line is found and its column is stable); trim the set only if a flag proves redundant *and* a test covers why.
5. **Result.** With every text-mutating option off the probe only rewrites leading whitespace, so line count and order are preserved: the placeholder's line index in the output equals its index in the probe input (newlines before the cursor within the window, + 1). Read that line's leading-space count and add the window opener's real column (UTF-16, from the document). As a guard, verify the located line actually starts with the placeholder after its indent — if not (or on any throw), structural fallback. The placeholder must not otherwise occur in the window: start from `__cljp__` and append a counter until `windowText` does not contain it.

Accepted property (documented, not fought): the probe returns the cljfmt-correct indent *assuming earlier window lines are cljfmt-clean*; on hand-misindented code the new line gets the would-be-correct column. This is how formatting tools converge buffers toward their style.

### `maxInner` from raw EDN (opaque-handle workaround)

The opaque `Config` cannot be inspected for rule depths, so discovery regex-scans the raw config EDN for `:inner\s+(\d+)` and computes `maxInner = max(2, matches)`. Over-approximation only widens the window (harmless); no config → 2.

### Config discovery

Per file: walk from the file's directory up to (and including) its workspace-folder root — or only the file's own directory when it is outside every folder — looking for `.cljfmt.edn` then `cljfmt.edn` in each directory (cljfmt's own order; `.cljfmt.clj` deliberately unsupported). First hit wins. Result per directory is cached: `{config, maxInner, path} | {error, path} | "none"`; effective config = `mergeConfig(defaultConfig, readConfig(raw))`. A `FileSystemWatcher` on `**/{.cljfmt.edn,cljfmt.edn}` invalidates the whole cache on create/change/delete (config changes are rare; no need for surgical invalidation). Monorepo sub-projects work by construction — the nearest config up the tree wins, matching the `projects.ts` model.

### nsContext cache

`readNsContext(doc.getText())` cached by `(doc.uri, doc.version)` with a single-entry-per-uri map cleared on document close. Derived lazily on the first Enter needing it. Format Document passes no nsContext — the full text carries its own `ns` form.

### Format providers

`DocumentFormattingEditProvider` and `DocumentRangeFormattingEditProvider` for `clojure`, registered at activation:
- **cljfmt engine, whole document:** `reformatString(fullText, config)`; if output differs, one whole-document `TextEdit`. Minimal-diff splitting is deferred until it's actually missed.
- **cljfmt engine, range:** expand to exact top-level form *offsets*, not line anchors. One `Scanner` pass over the document records a span `[openerTokenStart, closeOffset]` for every **delimited** top-level form: a span opens when the stack goes 0→1 in code mode (using the frame's `openOffset`, so `#(`/`#{` include the `#`) and closes when it returns to 0. Comments, strings, `#_` markers and bare top-level tokens never open spans (the scanner already skips them), and multiple forms on one line are distinct spans. The formatted slice is the union of spans intersecting the selection's offset range, from the first intersecting span's start to the last one's close; a selection intersecting no span yields no edits. Reformat that slice and emit one `TextEdit` over it — top-level spans need no column offset, and inter-span text (comments, blank lines) inside the slice is formatted as cljfmt would format it at top level.
- **structural engine:** "formatting" is re-indentation only (the setting description says so): a single top-down pass feeding the `Scanner` the progressively *rewritten* text — for each line compute the indent from the current stack (same rule as `indentColumnAt`), replace leading whitespace, and continue scanning the rewritten line so later columns are consistent. Lines starting inside strings are untouched (string content is sacred); blank lines stay blank; tab-indented lines are left alone (never guess tab width — same guard as `maintainIndent.ts`).
- On any cljfmt throw the providers return no edits (formatting a broken buffer should do nothing, not half-format); no notification from the formatting path.

### Parse-error surfacing (settled UX)

A broken config is *state*, so it lives in the status bar; the moment of breakage is an *event*, so it gets one notification:
- `src/fmt/configStatus.ts` owns a **dedicated** `StatusBarItem` (not the shared `statusSlot` — that slot is last-writer-wins for transient run verdicts, and a test verdict must not hide a persistent warning). Shown while the most recently *used* config file fails to parse: text `$(warning) cljfmt config`, `statusBarItem.warningBackground`, tooltip = parse error message + file path, `command` opens the file. Hidden when the config parses again, when discovery finds no config, or when the engine is `structural`.
- `onDidSaveTextDocument` for files named `.cljfmt.edn`/`cljfmt.edn`: try `readConfig`; on failure show one `vscode.window.showWarningMessage` with the message and path. Never notify from Enter/format calls.
- While broken, formatting proceeds with `defaultConfig` (matching cljfmt-js's own philosophy: broken config ≠ broken editor).

### Settings & docs

`clojurePulse.formatting.engine` in `package.json` (`enum: ["cljfmt", "structural"]`, default `"cljfmt"`), enumDescriptions stating: cljfmt = community rules + `.cljfmt.edn` discovery, byte-identical to the cljfmt CLI; structural = the fixed 2-space/alignment rule, and its Format Document is **indent-only** (no whitespace cleanup, no ns sorting). README gains a Formatting section (engines, config discovery, no `.cljfmt.clj`, format-on-save hint, the status-bar warning). `src/indent.ts` / docs header comments stop calling the scanner a "mirror" of clj-pulse's `indent.rs` — it is now the structural engine and fallback; the two may drift.

### Testing

- **Unit** (existing mocha/tdd suites under `src/test/`): discovery walk/cache/watch-invalidation (temp dirs), `maxInner` regex, structural reindent pass, window selection, probe column math against expected outputs **generated from the real cljfmt CLI and checked in as literals** (a comment marks them `verified against cljfmt 0.16.5`) — configs: defaults, `:function-arguments-indentation :cursive`, `:extra-indents` with a `#re` key and a namespace-qualified key (exercises nsContext).
- **Integration** (Extension Host, `xvfb-run -a npm test`): Enter with cljfmt (`(foo bar` + Enter → column 5, aligned under `bar`, where structural gives 2 — the visible rule difference; `let` bodies land at 2 under both engines and serve as a regression case), Enter fallback on unbalanced text, engine switch via workspace settings, Format Document + Format Selection, config status item shown/cleared (assert on the exported current-view accessor, as `statusSlot.test.ts` does).
- **Differential guard:** fixture files formatted through the real provider in the extension host must equal checked-in outputs produced by the cljfmt CLI for the same config.
